I decided to build a project that finds the most cost-efficient gas station near you by framing it as an optimization problem rather than a simple lookup. Most gas apps sort by price per gallon. The real problem is a multi-variable cost minimization across distance, fuel consumption, and price simultaneously. Driving further to a cheaper station is only worth it up to a specific break-even point that depends on your vehicle's MPG and current tank level. This app computes that breakeven for every nearby station and ranks them by total trip cost.
My core model takes your fuel level, tank capacity, and MPG as inputs and builds a cost function for each station that accounts for fuel burned in transit, gallons purchased on arrival, and the effective cost per gallon once transit is factored in. The output is a ranked list where the top result is the station that minimizes total spend, not just price at the pump.
Price estimation uses EIA state-level averages as a prior, then applies brand-level adjustments calibrated from observed market patterns across major chains. Deterministic noise is added per station using an MD5 hash so estimates are consistent across repeated calls without storing any state. The model degrades gracefully in data-sparse areas by falling back to state averages.
On the infrastructure side the backend is FastAPI with Python, pulling station location data from the OpenStreetMap Overpass API and computing a driving distance matrix via OSRM in a single batched request rather than one call per station. Location is resolved from GPS via Nominatim reverse geocoding or from IP with immediate discard after use for privacy compliance. The frontend is React Native with Expo.
The entire data pipeline runs on open, free data sources with no paid APIs required.
